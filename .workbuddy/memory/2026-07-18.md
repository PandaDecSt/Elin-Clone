## 战争迷雾 bug 修复 (game.js)

修复了 isometric 伪3D 战争迷雾抠图逻辑（game.js 迷雾块，约 1921-2100 行），共两段：红色"已探索不可见"段 + `destination-out`"可见抠图"段。

关键事实（供后续参考）：
- 真实墙体绘制在 `iso.js:drawBlockStack`：图集精灵 64px，`drawY=p.y-48-accumH`，`accumH += bt.h*WALL_H`。`drawTileWall`(iso.js:505) 是死代码。
- 常量 `TILE_W=64, TILE_H=32, WALL_H=32`。`gridToScreen`: gy+1=屏幕左下(西南,贴左侧面)、gx+1=右下(东南,贴右侧面)。
- `BLOCK_TYPES` 有 `h`(1.0/0.5/0.75) 与 `solid`(墙 true / 栅栏 wood_fence/stone_fence/iron_bars false)。
- 结论修正：单层满墙/均匀满墙堆叠原本几何是对的（i*WALL_H == accumH）；**只有混合高度/半墙堆叠**才因 `i*WALL_H` 与真实 `accumH` 不一致而错位。

本次改动：
1. 两段都改用真实累积高度 `accumH += bt.h*WALL_H`（原来是 `i*WALL_H`），修复半墙/混合堆叠错位。
2. 新增 `solidHeightPx(bx,by)` 辅助函数：只累加 `solid` 方块高度（栅栏不算遮挡）。
3. 侧面剔除改为逐层、按高度判断：`solidSW/solidSE < layerTop-0.01` 才抠该层侧面。红色段替换旧的 `.length>0` 全有全无判断；可见抠图段**新增**了这套剔除（原来无条件抠两侧面，会在可见墙紧邻雾墙处透洞）。
4. 顶面仍仅最顶层抠（原本正确，保留）。

未做（有意留白）：`world.js:computeVerticalVisibility` 算出的 `_visibleZ` 仍未接入正式迷雾（仅 debug 用），属增强非 bug，接入有回归风险。

## Block 战争迷雾渲染修复 (game.js:1991-2038)

### 问题
1. **阴影形状错误**：Block迷雾用单个`fillRect`矩形包围整个Block
2. **缺少邻接面剔除**：所有面都绘制迷雾，不判断相邻Block遮挡
3. **层级遮挡错误**：矩形迷雾延伸到Block下方，覆盖地板迷雾

### 修复方案
将Block迷雾从单个矩形改为**等距三面结构**绘制，与 `drawTileWall` (iso.js:505) 的面几何一致：

**代码位置**：`game.js` 约 1991-2038 行（第二趟 drawList 渲染循环中 `d.type === 'block'` 分支）

**核心改动**：
1. **顶面菱形**（始终绘制）：
   - 顶点：`(bp.x, bp.y-accumH-hh)` → `(bp.x+hw, bp.y-accumH)` → `(bp.x, bp.y-accumH+hh)` → `(bp.x-hw, bp.y-accumH)`
   - `hw=TILE_W/2=32, hh=TILE_H/2=16, accumH=blockHeightAt()*WALL_H`

2. **左侧面（西南面）**：邻接剔除后绘制
   - 四边形：`(bp.x-hw, bp.y-accumH)` → `(bp.x, bp.y-accumH+hh)` → `(bp.x, bp.y+hh)` → `(bp.x-hw, bp.y)`
   - 跳过条件：`blockHeightAt(gx, gy+1) >= blockHeightAt(gx, gy)`（南邻足够高时不可见）

3. **右侧面（东南面）**：邻接剔除后绘制
   - 四边形：`(bp.x, bp.y-accumH+hh)` → `(bp.x+hw, bp.y-accumH)` → `(bp.x+hw, bp.y)` → `(bp.x, bp.y+hh)`
   - 跳过条件：`blockHeightAt(gx+1, gy) >= blockHeightAt(gx, gy)`（东邻足够高时不可见）

**层级修正原理**：
- 原代码 `fillRect` 延伸到 `bp.y + TILE_H/2 + 48`，覆盖地板迷雾
- 新代码三面几何止于 `bp.y + hh`（地板菱形底部），不超出Block投影范围
- 渲染顺序：地板 → 地板迷雾 → Block精灵 → Block面迷雾，Block精灵自然遮挡地板迷雾

### 验证结果
- 差分测试（像素级对比有雾/无雾帧）：顶面 96%，左面 100%，右面 100%
- 视觉验收：Block迷雾呈等距三面形状，地板未被Block迷雾覆盖
- 邻接剔除：与相邻Block贴合的面正确跳过

## 装饰物系统重设计：贴图替代程序绘制

### 问题
原装饰物系统使用Canvas 2D程序绘制（`iso.js:drawDecoration`，236行switch/case），每种装饰物用手写代码画弧线、椭圆、贝塞尔曲线。视觉效果一般，且无法使用原版精灵。

### 解决方案
改用Elin原版图集`objs.png`(4096x4096)和`objs_S.png`(2048x2048)中的精灵贴图。

### 改动文件

1. **data.js:282-296** - `DECOR_TYPES`定义增加图集坐标：
   - 每种装饰物增加`atlas`(图集名)、`sx/sy`(图集坐标)、`sw/sh`(精灵尺寸)
   - 保留`minS/maxS`(缩放范围)和`light`(发光)属性

2. **iso.js:102-117** - 图集加载增加`objs`和`objs_S`：
   ```js
   'objs':    'assets/elin/objs.png',
   'objs_S':  'assets/elin/objs_S.png',
   ```

3. **iso.js:1102-1138** - `drawDecoration()`重写为贴图版：
   - 主逻辑：`ctx.drawImage(atlas, sx, sy, sw, sh, cx-dw/2, cy-dh, dw, dh)`
   - 发光装饰物(torch/crystal)附加径向渐变光晕
   - 图集未加载时回退到简单圆形
