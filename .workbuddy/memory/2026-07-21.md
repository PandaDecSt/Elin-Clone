## Elin 贴图映射数据「怎么读进游戏 / 读什么文件」调研 ✅
- **入口**：`SourceManager.Init()`（`Core.Instance.sources`）按字段反射收集所有 `SourceData`，依次调 `blocks.Init()/floors.Init()/objs.Init()/decos.Init()/things.Init()`… 每个 `SourceData.Init()` 读对应的 Source Sheet。
- **逻辑层文件 = Source Sheets**：xlsx（sheet名=类名：Block/Floor/Obj/Deco/Thing…），行格式 第1 header / 第2 type / 第3 default / 第4起数据；`RowMapping`(列名→列序号) 定顺序。`SourceBlock.CreateRow()` 用 `SourceData.GetInt/GetString/GetIntArray(列号)` 解析当前行。`tiles` 列=贴图编号数组（每方向/变体一个），如 `123,-123,456,-456`。
- **像素层 = RenderData + 图集**：`RenderRow.SetRenderData()` 用 `ResourceCache.Load<RenderData>("Scene/Render/Data/"+_idRenderData)` 载入 ScriptableObject。`RenderData.pass`(MeshPass)→`mat._MainTex`=图集PNG；`pass.pmesh.tiling`(Vector2)=网格行列数。
- **tile→像素换算（源码级确认）**：`RenderRow.SetTiles()` 与 `RenderData.ConvertTile()` 同一式 `_tiles[i]=tiles[i]/100*pmesh.tiling.x + tiles[i]%100` ⇒ tile=行×100+列，列数=tiling.x（floors/blocks 均32列）。`RenderRow.GetSprite()` 切图：`cellW=texW/tiling.x, cellH=texH/tiling.y`，`Rect(col*cellW, texH-(row+1)*cellH, cellW, cellH)`。
- **mod 替换**：`Texture Replace/<图集名>_<tile编号>.png`（如 obj_123.png）覆盖单格；`@obj` 自定义放 `Texture/<id>.png`；`.pref`(INI) 微调 pivot/阴影/缩放。
- **结论**：逻辑映射(xlsx)→JSON 我们已有；tile→rect 的权威来源是游戏内 RenderData 的 `tiling`+图集尺寸（floors 32×40 cell64×48 / blocks 32×32 cell64×64），已与之前 MEMORY 修正一致。本地 assets/elin 只有 PNG 无 tiling 元数据，故精确 rect 仍需纹理查看器/解析 RenderData 资源。

## 更正：游戏运行时读的是 xlsx，不是 txt（已源码+官方文档双确认）
- 我口头答过"游戏读导出的纯文本 txt"是**误述**，更正如下（官方 Basic Sheet Modding 指南原文："The formatted xlsx files add SourceData into the game" / "place your mod data — an xlsx file. This xlsx file will act as your Source Sheet"）。
- **运行时主加载格式 = xlsx**：Modder 把 `.xlsx` 放进 mod 包的 `EN/`（或 JP/CN）语言文件夹，游戏直接读 xlsx 作为 Source Sheet。`SourceManager.Init()`→`blocks.Init()` 等读的就是 xlsx。xlsx 本质 zip 包内 XML，由游戏代码解析。
- **`ImportSourceTexts/ExportSourceTexts(path)/UpdateSourceTexts` 是另一条文本工具通道**（开发者/debug/启动参数用），不是 Modder 主路径；不要把它误当成"游戏读 txt"。
- **xlsx 导出是谁做的**：① 编辑=电子表格软件（Excel/LibreOffice Calc/Google Sheets）；② 游戏原生读 xlsx，无"xlsx→txt 转换"步骤；③ 教程"export the Source sheets via launch arguments"=**游戏代码**把官方源表 dump 成 xlsx 给 Modder 当模板，不是 Excel 的"另存为"。
- **对 H5 复刻**：解析 xlsx→JSON 正好对上游戏真实源格式，方向正确；运行时吃 JSON（构建期解析掉，零成本）。

## 源码核实：Elin 如何解析「用哪个图集 PNG」（用户问"看源码"）
- **结论（颠覆之前的字符串映射假设）**：Elin **不解析 id 字符串来选图集**，也不从 tile 值选图集。它把 `_idRenderData` 当作 ScriptableObject 资产**名字**直接载入，图集由该资产序列化的 `pass`(MeshPass) 字段决定。
- **证据链（Elin-Decompiled）**：
  1. `Elin/RenderRow.cs::SetRenderData()`：`this.renderData = ResourceCache.Load<RenderData>(pathRenderData + idRenderData) ?? defaultRenderData;`（pathRenderData=`"Scene/Render/Data/"`）。`@` 前缀是别名引用另一个资产名。无任何对 id 字符串的模式匹配。
  2. `Elin/RenderData.cs`：`public MeshPass pass;`（序列化引用，非代码计算）；所有 Draw 用 `pass.batches`/`pass.pmesh.tiling`。
  3. `Elin/TextureManager.cs::Init()`：`AddBase(textureData.objs,"objs.png",tileMap.passObj)`、`passObjS→objs_S.png`、`passObjL→objs_L.png`、`passBlock→blocks.png`、`passFloor→floors.png`、`passRoof→roofs.png`、`passObjSS→objs_SS.png`…（pass↔PNG 固定绑定）。
  4. `Elin/RenderData.cs::ConvertTile(tile)=tile/100*(int)pass.pmesh.tiling.x + tile%100` — 行/列在 `pass` 自己的网格尺寸里解读（objs 64×64 / objs_S 32×32 / objs_L 32×32 / blocks 64×64）。
  5. `Elin/LayerTextureViewer.cs`：按 `data.tex`/`data.tileW`/`data.tileH` 逐纹理展示（每纹理独立 cell 尺寸），即从 `renderData.pass.texture` 读。
- **对 13 个 obj「校准」的定性修正**：校准 = 读出这 13 个资产真实的 `pass`（属于哪个 MeshPass/图集），与 tile 值无关（row×100+col 始终正确）。真值表写在游戏 `Scene/Render/Data/*.asset` 的 `pass` 字段里（随游戏发布，不在反编译 C# 仓库，也无法从 id 字符串推导）。非启发式来源只有两条：① 解析游戏 `.asset` 文件的 `pass` 字段；② 游戏内纹理查看器（读运行时 `renderData.pass.texture`）。
- **可执行方向（待用户给游戏目录或同意）**：若用户提供游戏安装目录，可用脚本解析 `Scene/Render/Data/*.asset`(YAML) 提取每个 `_idRenderData→pass→图集` 真值，彻底消除字符串启发式与人工校准。
